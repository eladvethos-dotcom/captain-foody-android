# קפטן פודי – אפליקציית אנדרואיד

פרויקט Android Studio שמריץ את אפליקציית קפטן פודי בתוך WebView מאובטח.
כל הקבצים של האפליקציה (HTML, עיצוב וקוד) ארוזים בתוך האפליקציה עצמה. אין שרת, ואין צורך בדומיין.

## מה יש בפרויקט

```
captain-foody-android/
├─ app/
│  ├─ build.gradle.kts              הגדרות בנייה: targetSdk 36, R8, חתימה
│  ├─ proguard-rules.pro
│  └─ src/main/
│     ├─ AndroidManifest.xml        הרשאות, גיבוי מוצפן, Safe Browsing
│     ├─ java/il/captainfoody/app/
│     │  ├─ MainActivity.kt         המסך היחיד והגדרות ה-WebView
│     │  └─ SecureWebViewClient.kt  שומר הסף: מה מותר לטעון ולאן מותר לנווט
│     ├─ assets/www/                האפליקציה עצמה
│     │  ├─ index.html              כולל מדיניות אבטחת תוכן (CSP)
│     │  ├─ app.css
│     │  └─ app.js
│     └─ res/                       אייקון, צבעים, מסך פתיחה, הגדרות רשת וגיבוי
├─ gradle/libs.versions.toml        גרסאות הספריות
├─ SECURITY.md                      דרישות האבטחה ואיך כל אחת מטופלת
└─ PRIVACY.md                       טיוטה למדיניות פרטיות (גוגל פליי דורש קישור)
```

## מה צריך

- [Android Studio](https://developer.android.com/studio), בגרסה העדכנית. JDK 17 מגיע איתו.
- טלפון אנדרואיד 8 ומעלה, או אמולטור מתוך Android Studio.

## בנייה והרצה

1. פתחו את Android Studio ובחרו **Open**, ואז את התיקייה `captain-foody-android`.
2. אם Android Studio מבקש ליצור את Gradle Wrapper או לסנכרן, אשרו. בפעם הראשונה הוא מוריד את Gradle ואת הספריות.
3. חברו טלפון עם **Developer options › USB debugging** פעיל, או הפעילו אמולטור.
4. לחצו **Run ▶**. גרסת הפיתוח מותקנת בשם `il.captainfoody.app.debug`, כך שאפשר להחזיק אותה ליד גרסת החנות.

## עדכון התוכן

כל שינוי באפליקציה עצמה נעשה בשלושת הקבצים שב-`app/src/main/assets/www/`.
אחרי כל שינוי:

1. מעלים ב-1 את `versionCode` ב-`app/build.gradle.kts`, ומעדכנים את `versionName` (למשל `1.0.1`).
2. בונים חבילה חתומה חדשה, כמו שמוסבר בהמשך.

אסור להוסיף ל-`app.js` סקריפטים או קישורים לאתרים חיצוניים. גם מדיניות האבטחה בדף וגם `SecureWebViewClient` יחסמו אותם. כך זה מתוכנן.

## פרסום בגוגל פליי לקבוצה קטנה

ההמלצה לשימוש של מעט אנשים היא **מסלול בדיקה פנימית (Internal testing)**. הוא תומך בעד 100 בודקים לפי כתובת מייל, והגרסה זמינה להם תוך דקות.

1. **חשבון מפתח:** נרשמים ב-[Google Play Console](https://play.google.com/console). יש דמי רישום חד פעמיים ואימות זהות.
2. **יצירת אפליקציה:** **Create app**, שם "קפטן פודי", שפת ברירת מחדל עברית, סוג App, חינמית.
3. **בניית חבילה חתומה:** ב-Android Studio בוחרים **Build › Generate Signed App Bundle › Android App Bundle**, ואז **Create new** כדי ליצור מפתח העלאה.
   - שמרו את קובץ המפתח ואת הסיסמאות במקום בטוח מחוץ לפרויקט. בלי המפתח אי אפשר לעדכן את האפליקציה.
   - אל תכניסו את המפתח או את הסיסמאות ל-git.
   - בוחרים `release`, ומקבלים את `app-release.aab`.
4. **Play App Signing:** בהעלאה הראשונה מאשרים שגוגל ישמור את מפתח החתימה הסופי. זו ברירת המחדל וההמלצה של גוגל.
5. **העלאה:** **Testing › Internal testing › Create new release**, מעלים את ה-`.aab`, ומוסיפים את כתובות המייל של הבודקים.
6. **מילוי הטפסים שבדף App content:**
   - **Privacy policy:** קישור לדף עם התוכן של `PRIVACY.md`. אפשר לפרסם אותו בכל מקום ציבורי.
   - **Data safety:** האפליקציה לא אוספת ולא משתפת נתונים. כל המידע נשמר בטלפון. הפרטים נמצאים ב-`SECURITY.md`.
   - **Ads:** אין פרסומות.
   - **Content rating:** ממלאים את השאלון. לאפליקציה כזו בדרך כלל מתקבל דירוג לכל הגילאים.
   - **Target audience:** בוחרים גילאים. אם מסמנים גם ילדים, חלים כללי Families של גוגל.
7. **שליחה:** הבודקים מקבלים קישור הצטרפות ומתקינים מגוגל פליי.

**לפני פרסום לכולם (Production):** בחשבון מפתח פרטי שנפתח אחרי נובמבר 2023, גוגל דורש קודם בדיקה סגורה (Closed testing) עם לפחות 12 בודקים במשך 14 יום. לבדיקה פנימית הדרישה הזו לא חלה.

## אבטחה בקצרה

- האפליקציה טוענת רק את הקבצים שארוזים בתוכה, וגם את שלושת הגופנים מ-Google Fonts. כל כתובת אחרת נחסמת לפני שהבקשה יוצאת מהטלפון.
- קישורי גוגל מפות נפתחים באפליקציית המפות. אי אפשר להוביל את המסך עצמו לאתר אחר.
- אין גישה לקבצים, למצלמה, למיקום או לאנשי קשר.
- הסיורים מגובים רק לגיבוי המוצפן של גוגל.

הפירוט המלא נמצא ב-`SECURITY.md`.
